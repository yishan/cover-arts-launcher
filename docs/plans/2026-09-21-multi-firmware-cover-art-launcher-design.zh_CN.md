# 多固件 Cover Art 启动器设计规范

状态：设计基线
目标：AI Passport、ESP32-C3、8 MB Flash、240×320 屏幕、三个实体按键
关联实施规划：[多固件 Cover Art 启动器实施规划](2026-09-20-multi-firmware-cover-art-launcher.zh_CN.md)

## 1. 产品定义

产品由三部分组成：

1. **玩法管理器**：电脑端浏览器安装器，通过 Web Serial 连接设备；首次安装 Launcher，后续新增、更新或替换玩法。
2. **玩法库**：常驻设备 `factory` 分区的 Launcher，以 Cover Art 轮播展示三个玩法位置并启动所选应用。
3. **玩法应用**：独立构建并安装到三个 OTA 槽之一的 app image。通用 ESP32-C3 玩法不要求接入 Launcher；可选契约只用于增加应用内返回能力。

这不是并发运行。任一时刻只运行一个玩法；选择另一个玩法时，设备重启进入对应 app 分区。

### 用户语言

| 内部术语 | 用户看到的名称 | 使用规则 |
| --- | --- | --- |
| factory Launcher | 玩法库 / 多玩法系统 | 不得描述为三个玩法之一 |
| OTA slot | 玩法位置 | 使用“位置 1、位置 2、位置 3” |
| child firmware/app | 玩法 | 例如点球、Pong |
| Web Serial installer | 玩法管理器 | 电脑端浏览器体验 |
| invalid app image | 安装未完成 | 必须同时给出恢复动作 |

`ota_0`、分区偏移和原始 subtype 等术语只出现在高级诊断中。

## 2. 已确认产品决策

1. 最终设备主界面是 Cover Art，不是文字槽位列表。
2. 固定展示三个玩法位置，轮播可以循环。
3. 中间卡片是当前选择；左右屏幕边缘分别露出另外两个位置的一部分。
4. Launcher 安装完成和首个玩法安装完成是两个独立状态。
5. 用户可以在三个位置都为空时结束首次设置；空玩法库是合法状态，不是错误。
6. 同源更新优先推荐原位置；否则推荐第一个空位置。替换不同玩法的已有位置必须由用户明确选择并确认。
7. 通用玩法是默认兼容路径。玩法通过校验后无需健康确认回调即可显示为已安装；用户复位或重新上电后返回 Launcher，原名称、封面和再次启动入口继续保留。
7. MVP 使用电脑端 Web Serial，SoftAP 安装属于后续阶段。
8. 封面和展示元数据以 sidecar 形式安装，并与 app image 的 SHA-256 绑定；不要求任意固件天然包含标准封面。
9. 最终 UI 不继承 meta-pass 的文字菜单视觉，只借鉴已验证的多启动和安装链路思想。

## 3. 体验架构

```text
电脑浏览器
  玩法管理器
    ├─ 一次性安装多玩法系统
    ├─ 读取三个玩法位置
    ├─ 校验/提取 app image
    ├─ 选择空位置或替换位置
    └─ 写入 app + 展示 sidecar
             │ USB / Web Serial
             ▼
设备 factory Launcher
  玩法库
    ├─ 扫描三个位置
    ├─ 展示 Cover Art 轮播
    ├─ 阻止空位置/坏位置启动
    └─ 选择目标并重启
             │ 标准 OTA 启动选择
             ▼
被选中的玩法
    ├─ 独立运行
    ├─ 已适配时确认健康
    └─ 用户要求时返回 factory
```

即使没有任何有效子应用，Launcher 也必须保持可用。MVP 中只有浏览器安装器可以修改玩法位置。

## 4. 端到端用户路径

### 4.1 首次安装多玩法系统

```text
在支持的电脑浏览器打开玩法管理器
  → USB 连接 AI Passport
  → 检测芯片和当前分区布局
  → 说明一次性存储布局变化
  → 确认安装 Launcher
  → 写入并校验完整 Launcher 镜像
  → 重启进入玩法库
  → 选择：
       安装第一个玩法
       暂不安装，进入空玩法库
```

警告必须说明一次性布局变化可能重置已有设置，不能让用户误以为后续替换玩法也会重写整台设备。

选择“暂不安装，进入空玩法库”属于成功完成，不能表现为取消、跳过错误或设置未完成。

### 4.2 安装第二或第三个玩法

```text
打开玩法页面或选择本地固件
  → 连接设备
  → 校验固件/芯片/大小/SHA
  → 读取当前位置清单
  → 推荐同源更新位置或第一个空位置
  → 确认目标
  → 写入 app image
  → 校验已安装 app SHA
  → 写入封面 sidecar
  → 报告成功并提示重启
```

日常安装玩法时，不得重写其他位置、Launcher、NVS 和 PHY。

### 4.3 替换或更新玩法

三个位置都已使用时，用户必须明确选择被替换的卡片。确认页同时写出旧玩法和新玩法，并说明另外两个位置不受影响。

目标推荐采用固定优先级：先查找相同 `source_id` 的已有位置并推荐原位更新；否则推荐第一个空位置；两者都不存在时才要求用户手动选择替换位置。本地文件没有稳定 source ID 时，按新玩法处理，不能自动选择已有位置。

一旦开始写 app，旧 app 不能自动恢复，只能重新安装。A/B cover 记录保护的是展示元数据，不是 app image 本身。

### 4.4 设备日常使用

```text
开机
  → 扫描位置
  → 显示当前 Cover Art
  → UP 选择左侧/上一个卡片
  → DOWN 选择右侧/下一个卡片
  → OK 启动可用玩法
  → 设备重启进入该玩法
```

空卡片按 `OK` 打开安装帮助；安装未完成卡片按 `OK` 打开恢复帮助。两者都不能改变启动目标。

### 4.5 返回玩法库

通用玩法不需要编写任何 Launcher 专用代码。Launcher 把每次选择设置为一次性 OTA 启动。玩法持续运行到用户复位或重新上电，随后由 ESP-IDF rollback 返回 factory Launcher。此时产生的 `ABORTED` OTA 状态表示本次一次性游玩已结束，不表示已校验镜像损坏，因此原名称、封面和再次启动动作继续保留。

可选的已适配玩法可以在自己的菜单或封面页提供“返回玩法库”。玩法可以先保留内部导航，例如游戏中长按 OK 先回游戏自己的封面，再在封面长按 OK 返回玩法库。

v1 不设置自动游玩超时，也不要求第三方开发者确认启动。明确的 OTA 镜像校验失败仍保持不可启动，并进入恢复帮助。

## 5. 设备信息架构

量产体验包含五类界面及其状态变体：

| 界面 | 目的 | 主要操作 |
| --- | --- | --- |
| 启动/扫描 | 初始化显示并检查位置 | 自动跳转 |
| Cover Art 玩法库 | 选择可用、空或未完成位置 | UP、DOWN、OK、长按 OK |
| 位置详情 | 显示标题、版本、大小、状态和来源摘要 | 返回；需要时打开帮助 |
| 安装/恢复帮助 | 说明 USB 安装或修复方法 | 返回 |
| 启动/错误过渡 | 确认启动或说明校验失败 | 自动重启或返回 |

产品中不存在长期使用的文字列表主界面。文字列表只能作为工程联调阶段界面。

## 6. Cover Art 主界面规范

### 6.1 240×320 竖屏布局

| 区域 | 范围 | 内容 |
| --- | --- | --- |
| 顶栏 | `y=0..31` | 左侧“玩法库”，右侧电量 |
| 封面舞台 | `y=36..199` | 中央 120×160 封面和两侧露出 |
| 标题 | `y=206..233` | 居中玩法标题或位置状态 |
| 元数据 | `y=236..253` | 版本和“位置 n / 3” |
| 位置指示器 | `y=258..275` | 三个圆点/状态符号 |
| 操作提示 | `y=282..319` | UP 上一个、OK 动作、DOWN 下一个 |

选中封面约位于 `x=60, y=38`，尺寸为 `120×160`。左右相邻位置各使用 `36 px` 切片，其中约 `34 px` 可见、其余 `2 px` 收在中央框后。两侧以约 60% 不透明度显示，当前卡片保持完整对比度。

### 6.2 轮播顺序

```text
选中位置 1：左侧位置 3，右侧位置 2
选中位置 2：左侧位置 1，右侧位置 3
选中位置 3：左侧位置 2，右侧位置 1
```

两侧露出和三个位置指示器必须同时存在。两侧露出表达“还有内容”，指示器表达总数和当前位置。

### 6.3 按键映射

| 输入 | 可用位置 | 空位置 | 安装未完成位置 |
| --- | --- | --- | --- |
| `UP` 单击 | 左侧/上一个卡片 | 左侧/上一个卡片 | 左侧/上一个卡片 |
| `DOWN` 单击 | 右侧/下一个卡片 | 右侧/下一个卡片 | 右侧/下一个卡片 |
| `OK` 单击 | 启动 | 安装帮助 | 恢复帮助 |
| `OK` 长按 | 位置详情 | 系统/帮助详情 | 诊断详情 |

实体键名是 UP/DOWN，而轮播方向是左右，因此 v1 必须保留“UP 上一个、DOWN 下一个”的屏幕提示，不能只依靠动画教学。

位置详情、安装帮助、恢复帮助和诊断等所有二级界面统一使用 `OK` 长按返回 Cover Art 玩法库；`OK` 单击可以执行页面上唯一的主要动作。试运行位置与可用位置按键一致：`OK` 启动试运行，`OK` 长按进入详情。app 有效但封面无效的位置也采用可用位置按键映射。

### 6.4 位置状态视觉

| 状态 | 中央卡片 | 两侧露出 | 主要动作 |
| --- | --- | --- | --- |
| 可用 | 已安装封面 | 真实封面边缘 | 启动 |
| 空 | 带 `+` 的中性占位图 | 灰色边缘和位置编号 | 添加玩法帮助 |
| 试运行 | 封面加小型“试运行”标记 | 封面边缘加圆点 | 启动试运行/详情 |
| 未完成/无效 | 带 `!` 的占位图 | 警告边缘 | 修复帮助 |
| 封面损坏、app 有效 | 内置占位图 | 占位图边缘 | 仍允许启动 |

颜色不能成为唯一状态表达；必须同时使用 `+`、`!`、标签和动作文字。

### 6.5 三个位置全空

三个空位置仍可切换。当前卡片显示：

```text
[ 带 + 的中性封面 ]
空位置
位置 1 / 3
连接电脑添加玩法
```

两侧露出另外两个带编号的空位置。不得出现错误条、强制设置、倒计时或自动联网流程。

### 6.6 动效

- MVP 采用 120–160 ms 方向滑动，或即时切换加短暂边缘高亮。
- 只更新封面、标题和指示器区域，不持续全屏重绘。
- 不实现 3D 透视、模糊、弹簧物理，也不让三张完整封面同时常驻 RAM。
- 只有选择状态一致后才继续处理按键；连续输入不能让封面、标题和指示器错位。

## 7. 视觉与内容规则

- 使用安静的深色中性舞台，让用户封面成为视觉主体。
- 当前封面使用 1–2 px 聚焦边框；两侧用降低亮度而不是模糊。
- 系统状态色只用于空、可用、试运行和警告。
- 顶栏和按键提示不得覆盖封面。
- 电量读取失败时隐藏数值或显示不可用状态，不能改变封面布局。
- 长标题在视觉上截断，不能引起布局跳动；详情页保留完整标题。
- 保存 UTF-8 标题用于身份和诊断。Launcher 标题字库覆盖可打印 ASCII、CJK 标点、全角字符和 GB2312 一级字表的 3755 个常用简体汉字。字表外的生僻字显示占位符；如未来需要不受限中文，可再扩展有界的标题位图方案。
- 封面图不能承载必须阅读的操作说明；操作说明使用真实 UI 文字或固定系统资产。

## 8. 电脑端玩法管理器界面

MVP 需要 Web Serial，因此面向受支持的桌面 Chromium 浏览器。不支持或移动浏览器显示环境说明，不能展示一个无法工作的连接按钮。

| 界面/状态 | 必须内容 |
| --- | --- |
| 欢迎与环境检查 | 支持浏览器、USB 要求、开始操作 |
| 设备连接 | 串口选择、芯片/设备检测、重新连接引导 |
| 首次安装系统 | 存储布局警告、受影响数据、确认/取消 |
| 玩法来源与校验 | 玩法 URL 或本地文件、封面预览、芯片/格式/大小/SHA 结果 |
| 位置管理 | 三张位置卡片、封面、标题、版本、状态和推荐目标 |
| 替换确认 | 新旧玩法、受影响位置、其他位置、恢复警告 |
| 安装进度 | 检查、提取、写 app、校验 app、写封面、完成 |
| 成功 | 已安装位置、设备重启指引、继续安装入口 |
| 失败/恢复 | 精确失败阶段、位置安全状态、重试/重连、日志导出 |

这些可以是同一向导的状态，不必成为独立路由。

### 位置选择规则

1. 若传入玩法具有稳定 `source_id` 且设备已存在相同来源，推荐该位置原位更新。
2. 否则推荐第一个空位置。
3. 开始写入前允许“更改位置”。
4. 三个位置均已使用且不是同源更新时，必须明确选择，不能自动替换。
5. 更新或替换任何已有位置仍然必须确认。
6. 提取后的 app 超过 2 MiB 或设备布局无法识别时，禁用目标。
7. factory Launcher 不出现在可选清单中。

### 替换确认文案

```text
将位置 2 的“旧玩法”替换为“新玩法”？
位置 1 和位置 3 不受影响。
开始写入后，旧玩法只能通过重新安装恢复。
```

不能声称共享 NVS 数据会被删除。应用数据清理不属于 MVP，不能与镜像替换绑定。

## 9. 安装进度与失败行为

进度显示真实阶段，而不是装饰性百分比：

```text
✓ 检查固件
✓ 提取应用
● 写入位置 2       68%
○ 校验应用
○ 写入封面元数据
○ 完成
```

- 开始擦除 app 后锁定目标位置。
- 只有已安装 app SHA、SHA 绑定信任收据和可选 cover 记录校验完成后，才能显示完整成功；仅封面失败时使用下述明确的“部分成功”状态。
- 写 app 中断时，目标变为“安装未完成”，不能启动。
- app 校验通过后写封面失败时，报告部分成功：app 保持可选择、可使用内置占位图启动；玩法管理器提供“只重试封面”，不重写 app。
- v1 不续传残缺 app。断线后重新连接，从所选位置的 app 擦除/写入开始重做。首次完整系统安装中断后也从头重做；写入稀疏 merged image 前，显式擦除并校验三个 OTA slot、六个 cover bank 和 `otadata`，避免旧字节被识别成已安装玩法。ROM 下载模式作为恢复入口。
- 日常位置安装不改变其他位置和 Launcher。
- 错误信息指出失败阶段和下一步；只有展开高级诊断才显示原始偏移。

## 10. 位置与元数据契约

每个位置向 Launcher 和玩法管理器提供以下逻辑字段：

| 字段 | 用途 |
| --- | --- |
| `slot_id` | 稳定物理位置 `0..2` |
| `state` | 空、无效、试运行或可用 |
| `source_kind` | 玩法 API 或本地文件 |
| `source_id` | 如 `play:281` 的稳定身份；本地文件可为空 |
| `title_utf8` | 展示身份和诊断 |
| `version` | 用户可见的已安装版本 |
| `firmware_image_sha256` | app 与展示元数据绑定 |
| `cover_format`、尺寸、长度、CRC | 严格封面解码和边界 |
| `generation` | 选择最新有效的 A/B 展示 bank |
| `trust_source` | 精确安装收据、旧版 SHA 绑定封面或兼容模式 |

v1 封面格式固定为 120×160 RGB565。Launcher 分别校验 app 和封面；封面缺失或损坏不能让合法 app 失去启动资格。

### 10.1 常驻玩法信任策略

玩法管理器在 app 写入并读回校验后，将一条 256-byte 信任收据写入 `covers` 分区未使用尾部。每个 slot 使用两个 4 KiB bank，按 generation 选择最新有效记录。记录绑定 `slot_id`、app 实际长度和完整 app SHA-256；标题、Source ID 或相同文件名都不能继承信任。只有收据读回校验成功后，新安装才进入“已验证常驻”状态。封面随后独立提交，封面失败不撤销已经成立的信任。

为保持既有通用玩法可用，迁移顺序是：精确收据 → 与当前 app SHA 匹配的旧版封面清单 → 旧通用兼容模式。兼容模式仍允许启动，但日志和管理页不得把它显示成“已验证常驻”；用户用管理器重新核验同一 app 后可补写收据。该策略代表“用户通过本机管理器完成过精确镜像校验”，不是开发者签名，也不是恶意固件沙箱。

信任 bank 使用绝对地址 `0x7e0000..0x7e5fff`，不改变分区表。擦除某个位置时，同时擦除它的 app、两个 cover bank 和两个 trust bank；完整系统迁移清空三个位置的全部收据。

### 10.2 启动性能测量

Launcher 输出结构化 `PERF` 日志：开机扫描与信任分类、UI 就绪、选中 slot 的再次检查、信任查找、ESP 镜像校验和发送重启前时刻。三个 slot 必须在同一固件、同一供电和同一串口配置下各测至少三次，分别报告中位数和最大值；不得用桌面模拟器结果代替真机启动性能。

## 11. 可选的子应用接入契约

通用玩法没有强制接入契约。它通过上述一次性启动策略完成安装、展示、启动、复位/重新上电返回和再次启动。

选择增加应用内返回动作的玩法必须：

- 只有到达可用状态后才确认健康；
- 提供可发现的“返回玩法库”动作；
- 重启前先把 factory 设置为下一启动目标；
- 不写 Launcher、其他 OTA 槽、其他位置的 cover bank 或分区表；
- 慢存储、音频和网络操作不进入按键回调或 LVGL 临界区。

接入只用于增强无需硬件复位即可返回的体验，不是安装或启动前提。

## 12. 非目标

- 同时运行多个玩法。
- 在 8 MB 设备安装超过三个玩法。
- 把语言、难度或游戏模式作为独立位置。
- MVP 中的设备端应用商店或后台下载。
- 复杂 3D Cover Flow。
- 隔离恶意安装固件的安全沙箱。
- 替换不相关固件时保证保留其应用专用数据。

## 13. 验收标准

### 理解度

- 首次用户无需看到 OTA 术语，也能说明系统有三个玩法位置。
- 用户能识别当前位置，并从主界面感知另外两个位置。
- 替换前，用户能说出将被删除的玩法和不受影响的两个位置。

### 设备行为

- 三个位置全空是成功且稳定的状态。
- 空位置和安装未完成位置绝不成为启动目标。
- 合法 app 的封面元数据损坏时使用占位图，app 仍可启动。
- 连续输入时，UP/DOWN 导航、标题、位置指示器和两侧露出保持一致。
- 切换卡片 100 次没有单调 heap 泄漏；三张完整封面绝不同时常驻 RAM。
- 左右相邻位置始终各露出约 `34 px` 边缘，其状态符号和三个位置指示器与当前卡片同步。

### 安装器行为

- 首次 Launcher 安装和首个玩法安装可以分别完成。
- 首次系统安装写入并校验完整 Launcher 镜像；中断后通过 ROM 下载模式重新连接，并从头执行完整系统写入。
- 适用时，app-only 和 merged 镜像得到相同的校验后 app image。
- 超大、截断、错误芯片或 SHA 不匹配镜像在改变启动目标前被拒绝。
- 安装中断产生明确安全状态和恢复动作。
- 日常替换位置不重写 Launcher、分区表、NVS、PHY 或无关位置。

### 证据报告

分别报告 build、host tests、device tests 和剩余未验证项。浏览器模拟或主机测试不能替代目标设备的断电、按键、Web Serial 或 rollback 验收。

## 14. 交付阶段

1. **契约原型**：固定布局、元数据 codec、位置状态模型和主机测试。
2. **文字联调**：验证扫描、选择、启动、返回和回滚；文字列表不作为产品 UI。
3. **玩法管理器**：首次安装、位置清单、app 提取、Web Serial 写入、校验和恢复。
4. **Cover Art UI**：正式轮播、两侧露出、全空状态、详情和占位图行为。
5. **真机验收**：重复切换、中断写入、断电、heap 稳定性及已适配/未适配玩法。
6. **可选 SoftAP**：只有 1–5 通过并实测 Flash/RAM 余量后进入。

## 15. 待定设计项

- “玩法库”和“玩法管理器”的最终产品名称。
- 最终安装器地址，以及设备帮助页是否提供二维码。
- 品牌视觉主题、占位图插画和聚焦边框样式。
- 未来是否由浏览器为内置常用字表以外的中文字符保存预栅格标题 mask。
- 各现有玩法在保留内部导航的前提下，采用什么返回手势。

这些事项可以改变视觉资产和文案，但不改变已经确认的三位置架构和用户路径。
