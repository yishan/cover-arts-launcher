# 任意删除、逻辑重排与空洞复用

状态：已实现；v1.5.0 主机验证与连接真机验证已完成

## 用户可见行为

- 可以删除任意已安装玩法，不再局限于最后一个位置。
- 保留封面会立即补齐逻辑空位：删除位置 2 后，原位置 3 变为位置 2。
- 保留玩法的 App 字节继续留在原 Flash 地址，因此删除时不复制固件。
- 后续安装优先使用能够容纳“对齐后 App + 64 KiB DPS1 sidecar”的最小已释放空间；没有合适空洞时才使用尾部空间。
- 如果总空闲字节足够但过于碎片化，安装会在擦除前停止，并提示没有足够大的连续空间。本版本不自动执行物理整理。

## 事务顺序

1. 校验当前完整玩法库，计算新的连续逻辑身份。
2. 对每个需要前移的玩法，把活动 DPS1 记录复制到非活动 bank，只修改 generation、逻辑位置 ID 和记录 CRC。
3. 提交并读回校验带 MD5 的新分区表。
4. 清空并校验 `otadata`。
5. 重新扫描全部保留玩法，并与删除前库存逐一核对固件 SHA。
6. 擦除被删除玩法的物理分配区域，并抽样校验首尾。

第 3 步之前，旧分区表仍会选择旧的活动 DPS1 记录；第 3 步之后，新分区表会选择预先写好的新记录。即使最后擦除失败，已删除玩法也不会重新进入目录；以后复用该范围前会再次完整擦除。

## 持久启动次数

启动次数仍保存在 NVS，但 Launcher 会在容量上限内搜索与当前玩法稳定身份匹配的所有位置记录。如果计数仍保存在旧逻辑位置键下，Launcher 会把它迁移到当前键，并删除旧键。官方玩法使用 Source ID 作为身份；本地玩法没有 Source ID 时使用固件 SHA-256。

## 验收

主机测试覆盖删除首位／中间／末位、物理地址与逻辑顺序不同、最小适配空洞分配、碎片化拒绝、DPS1 身份重写和保留玩法重新扫描。连接真机测试覆盖 v1.5.0 Launcher 启动与玩法管理器写入链路。分区表提交前后主动断电及穷举碎片场景仍属于故障注入测试，不作为常规发布验收步骤。
