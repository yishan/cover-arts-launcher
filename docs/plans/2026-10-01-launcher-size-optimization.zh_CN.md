# Launcher 体积优化

## 范围与实测

这是基于 v1.5.0 的未发布代码优化候选版，使用固定的 ESP-IDF 5.5.3 与 LVGL 9.5.0
构建。不改变分区、已安装玩法、管理器协议、标题字集或界面布局，也不替换已经发布的
v1.5.0 Release 文件。

| 测量项 | v1.5.0 本地构建 | 优化候选版 |
| --- | ---: | ---: |
| 应用程序二进制 | 920,816 字节 | 737,040 字节 |
| 仅标题字形位图 | 229,532 字节 | 198,761 字节 |
| Factory 预留分区 | 1,507,328 字节 | 不变 |
| 空设备玩法区域 | 6.4375 MiB | 不变 |
| 完整合并镜像 | 8,388,608 字节 | 不变 |

程序节省 183,776 字节（179.47 KiB，19.96%）。完整镜像为 8 MiB，即十进制的
8.39 MB，是因为镜像覆盖到位于 `0x7fe000` 的 OTA 启动选择数据，并不代表 Launcher
代码有 8 MiB。擦除填充不能算作可执行代码体积。剩余玩法空间还取决于已安装程序的
分配、对齐，以及每个玩法 64 KiB 的 Sidecar。

## 已实现的调整

- 编译改为体积优先优化。
- 关闭未使用的 LVGL 控件，保留基础对象、图片、标签及其默认主题样式。
- 使用带预过滤的 LVGL 无损压缩处理 16 px、2 bpp 字库，保留全部 3755 个 GB2312
  一级汉字及原有标点、ASCII 字符覆盖。
- 主机预览与固件的控件配置保持一致，并加入静态测试保护。

## 验证

固件构建、合并镜像及分区校验通过。仓库检查、主机测试通过。LVGL 原生预览通过，
包含反复切换页面的测试。与 v1.5.0 未压缩字库对比全部 4,008 个支持字形，覆盖范围、
排版度量及解码像素完全一致。

复现无损对比时，将未压缩参考字库保存在候选版源码树之外，不提交重复的大字库：

```bash
cmake -S tests/launcher_preview -B build/font-check \
  -DLVGL_DIR="$PWD/managed_components/lvgl__lvgl" \
  -DLAUNCHER_REFERENCE_FONT=/absolute/path/to/uncompressed-font.c
cmake --build build/font-check --parallel 6
build/font-check/launcher_font_equivalence
```

真机测试尚未执行。字体解压会增加短时的逐行缓冲及解码工作；实际切换速度、剩余堆、
中文显示与长时间稳定性需在设备上验证。该候选版未刷入、未提交、未发布。

## 独立的下一步：回收 Factory 余量

仅缩减代码不会扩大玩法区域。可选的紧凑布局可以将 Factory 大小由 `0x170000`
缩小到 `0x0f0000`，将玩法区域起点由 `0x180000` 降至 `0x100000`，回收 512 KiB，
使空设备玩法区域达到 6.9375 MiB。Factory 余量为 983,040 减去最终发布程序大小；
按本候选版计算，剩余 246,000 字节（约 240 KiB）。

此布局尚未实现。必须先决定迁移策略，并协调 Launcher 与管理器的调整：依据设备实际
Factory 分区确定安全的玩法区域边界，兼容已有分配，并限制旧固件与新版管理器的混用。
不能只为逻辑编号重排而搬移已安装程序或覆盖其存储。紧凑布局的完整系统安装与保留数据
的 Launcher 更新应作为不同流程。

不能直接截断完整镜像末端的 OTA 初始化范围，否则可能留下旧的启动选择状态。缩小社区
下载文件需要独立验证打包与安装约定，不只是压缩代码。
