# Launcher 紧凑分区

状态：实现已纳入 v1.6.0 发布准备。下方候选版身份与检查是开发阶段的历史记录，不是
CI Release 产物。当前范围与验证边界见 [v1.6.0 发布说明](../releases/v1.6.0.zh_CN.md)。

## 容量与兼容性

| 项目 | 已发布 v1.5.0 布局 | 紧凑布局 |
| --- | ---: | ---: |
| Factory 起点 | `0x10000` | 不变 |
| Factory 预留 | `0x170000`（1,472 KiB） | `0x0f0000`（960 KiB） |
| 玩法区域 | `0x180000..0x7f0000` | `0x100000..0x7f0000` |
| 空设备玩法容量 | 6.4375 MiB | 6.9375 MiB |
| 标准 OTA 选择区 | `0x7fe000..0x800000` | 不变 |

紧凑布局准确释放 512 KiB。每个玩法仍需按 64 KiB 对齐，并预留 64 KiB Sidecar，
所以单个 App 镜像最大为 `0x6e0000` 字节。实际剩余空间取决于已安装分配与碎片。
NVS、PHY、Factory 起点、bootloader 和分区表地址不变。完整合并镜像仍为 8 MiB：
缩小可执行代码不会消除用于初始化 OTA 选择区的擦除填充。

## 已实现内容

- 新的完整系统构建采用紧凑 Factory 预留。保留已有体积优化代码和无损压缩中文字库。
- Launcher 根据当前 Factory 分区推导经过审核的玩法起点，识别两种 Factory 大小，
  拒绝不安全的玩法边界。
- 管理器根据设备实际分区表及其 MD5 识别布局，不依赖版本文本或固定起点。
  分配、删除、空洞复用、扫描与目录提交均显式保留该布局。
- 普通安装和删除不会更改 Factory 大小，不增加自动搬移或物理空间整理。
- 完整系统安装会先验证传入目录为空、Factory 长度、ESP 校验和/SHA 与分区容量，
  再执行擦除。擦除范围跟随传入布局，包含新增的前部空间。

## 升级选择

1. **保留当前布局：** 已发布版仍可使用。经审核的 Factory 程序单独更新可以保留
   分区表、NVS、玩法、封面和统计，但不会增加 512 KiB。本次不新增管理器的
   “仅更新 Factory”按钮。
2. **采用紧凑布局：** 确认破坏性提示后执行新版完整系统初始化。已安装玩法和封面
   会被删除，需要重新安装。需要保留的玩法数据应通过该玩法支持的导出方式保存。
   不保证所有第三方玩法的私有数据均可导出或恢复。

网页的分段初始化保留 NVS/PHY，但不保留被删除的应用，也不保证其存档兼容。
从 `0x0` 写入完整合并镜像可能重置 NVS/PHY。单独授权的整片擦除会删除全部数据。
以上操作不能混为一谈。不要求备份原固件，也不能用写入成功推断数据已保留。

应先部署新版管理器，再向普通用户提供紧凑固件。旧管理器使用固定边界，无法识别
紧凑分区，不应再用于初始化或管理此布局。新版管理器兼容两种动态布局，不会静默
迁移已有设备。使用旧完整系统镜像降级同样会破坏已安装内容。

## 验证与真机交接

主机检查覆盖容量增量、两种分配边界、完整空间耗尽、16 玩法上限、任意删除、逻辑
重排、空洞复用、空库扫描、未知布局、超大 Factory、损坏镜像/分区表及传入擦除范围。
既有完整验证流程检查实际 Factory 容量和合并镜像，并保留匹配的调试文件。

真机需另行验收初始化、中文画面与按键、首个玩法位于 `0x100000`、多玩法安装、
在新增区域删除与复用、启动/返回、重启、元数据和长期字体解码。主分区表提交期间
断电仍可能需要 ROM 恢复；紧凑分区不消除该风险。本文不授权刷机或发布。
