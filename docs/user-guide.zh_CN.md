# Cover Arts Launcher 用户指南

## 设备按键

- `Up` / `Down`：在三个位置之间移动。
- `OK`：启动居中的玩法。
- 空位置：可以被选中，但不会启动 App。
- 重启或重新上电：返回 Launcher，同时保留已校验的玩法。
- 仅限已适配玩法：在该玩法已有封面页或开始页长按 `Up`，直接返回 Launcher。该快捷操作
  不是安装要求，也不应影响游戏过程。

## 安装玩法

玩法管理器接受官方 Play 详情 URL 或本地 `.bin`。使用官方 URL 时，会读取可用的标题、版本、
Source ID、固件哈希和封面。使用本地文件时，请核对识别到的固件，并自行提供展示信息。

写入前，管理器会预览并在浏览器本地转换封面，验证 ESP32-C3 镜像、确认其能放入选中的
2 MiB 位置，并检查标题字形覆盖。随后只写入选中的 App 位置及其元数据，其他位置不变。

安装后请区分两个状态：

1. 浏览器完成 Flash 校验并发送了复位请求。
2. 用户在设备上看到了新封面，并成功启动玩法。

只有第二项属于真机确认。

## 替换或擦除位置

选择已有玩法的位置并安装另一个玩法，会在明确确认后只替换该位置。“擦除所选位置”会删除
该位置的 App、封面 bank 和信任记录，不会擦除 Launcher、NVS、PHY 数据或其他两个位置。

## 通用玩法和可选返回支持

兼容的通用玩法无需修改源码即可安装和启动，运行后仍保留在设备中。如果玩法没有接入可选的
封面页返回协议，用户重启或重新上电即可返回 Launcher。

创作者可以使用[兼容 Skill](../skills/ai-passport-cover-arts-launcher/SKILL.zh_CN.md)。
接入时不得增加全局 `Up Long` 处理，也不得修改游戏、设置或无关页面中的按键行为。

## 常见恢复操作

- **浏览器断开：** 重新连接并扫描后再判断安装状态，不要依赖已经过期的网页提示。
- **玩法写入失败：** 管理器确认该位置不可启动后重试，或先明确执行擦除再安装。
- **封面写入失败：** 选择只重试封面；管理器提供时，也可使用占位封面完成。
- **网页提示已发送复位，但显示未变化：** 重新连接、重新扫描，再手动重启设备。网页会分别报告
  “已发送复位请求”和“用户已观察到设备画面”。
- **标题或封面不正确：** 先重新扫描。只有与已安装 App 哈希绑定且通过完整性校验的元数据才会被接受。
