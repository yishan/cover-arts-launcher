03

WHAT THE SKILL CHANGES

使用 Skill 后会发生什么

即使完全不接入，通用玩法仍可被 Cover-Arts Launcher 安装和启动，只是返回 Launcher 需要重启设备或重新上电。Skill 提供的是“封面页快捷返回”，不是安装或启动的兼容资格。

发生什么过程

  1. 01
    交给 Agent

    开发者提供 $ai-passport-cover-arts-launcher 和当前玩法项目。

  2. 02
    先检查边界

    Agent 检查按键系统、状态机和已有封面／开始页，不直接改代码。

  3. 03
    能识别才接入

    只有能可靠识别封面状态时，才加入带状态门控的快捷返回并运行测试。

  4. 04
    无法识别就停止

    Agent 会说明阻碍，不全局监听 Up Long，也不擅自新增封面页。

Skill 不自动授权烧录、commit、push 或发布；这些操作仍需开发者明确确认。

接入前／接入后

BEFORE · 通用兼容
重启返回玩法库

玩法可正常安装和启动。需要切换游戏时，重启设备或重新上电返回 Launcher。

AFTER · 可选增强
封面页快捷返回

仅在玩法已有封面／开始页长按 Up 约 1.5 秒返回 Launcher。游戏、设置、暂停、结算及其他状态中的 Up Long 保持原有行为。

玩法标题、封面、规则、存档和正常启动流程不变；factory Launcher 缺失或无效时，只记录错误并保持玩法运行。

代码层面变化

通常只增加一个小型 launcher_contract ESP-IDF 组件，并在现有输入分发点加入状态门控：

if (app_state == APP_STATE_COVER &&
    input.event == UP_LONG) {
    launcher_contract_return_to_factory();
}

组件在运行时查找并校验 factory，设置下次启动分区后重启。不能硬编码 factory 地址，也不能全局监听 Up Long。

不会发生的变化

  • 不改变玩法 UI 风格、游戏规则、分区表、标题封面或存档
  • 不增加网络依赖，也不要求 Launcher SDK
  • 不把 Up Long 注册成全局快捷键
  • 不要求所有社区玩法必须适配
  • 除非创作者明确要求，不新增提示文字或弹窗
